CFC.DIG Structure:
	1. File Records

For every file being packed there is an PacketRecord struct here. In every CFC.DIG the
"offset" field is stored as a "CD Sector". This means the packets are aligned into cd sectors of 2048 bytes (0x800).

	2. Data

Packet data, all data here is stored in the same order as the packet records but this doesn't
technically have to be true given the PacketRecord struct. Data is sometimes compressed, usually,
a packet isn't compressed if the first 4 bytes are null.

Compression:

For info about compression check out here: https://github.com/Raw-man/Racjin-de-compression
It contains original C++ (de)compression code. The code for (de)compression provided by this
tool is from the above repo just converted to C#.
